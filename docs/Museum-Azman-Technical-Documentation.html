1. Document Purpose

This document provides technical guidance for developing, deploying, operating, and maintaining Museum Azman. Target audiences include developers, DevOps/infrastructure engineers, technical support teams, and system administrators.

2. System Overview

Museum Azman is a web-based collection management platform supporting:

  • Artwork inventory lifecycle
  • Artist and location management
  • Artwork movement tracking
  • Reporting and export (CSV/PDF)
  • User and role administration
  • Settings and backup operations
  • Installable PWA behavior

3. Technology Stack

3.1 Backend

  • php ^8.2
  • laravel/framework ^12.0
  • laravel/tinker
  • barryvdh/laravel-dompdf
  • bupple/laravel-ai-engine (optional)

3.2 Frontend

  • Blade templates in resources/views
  • Vite build pipeline
  • Tailwind CSS 4
  • Vanilla JavaScript for suggestions, modal interactions, AJAX flows, and PWA

3.3 Data and Storage

  • Database configurable via Laravel (sqlite default in .env.example)
  • Backup table-snapshot support for mysql, pgsql, and sqlite
  • Public disk for media and local private disk for backup JSON files

4. Project Structure

  • app/, bootstrap/, config/, database/, public/, resources/, routes/, storage/, tests/
  • Controllers: app/Http/Controllers
  • Models: app/Models
  • Services: app/Services
  • Console commands: app/Console/Commands

5. Architecture

5.1 Runtime Request Flow

  1. Client request
  2. Route resolution in routes/web.php
  3. Middleware checks (guest, auth, admin)
  4. Controller orchestration
  5. Eloquent model operations
  6. Optional service layer processing
  7. Blade/JSON/file response

5.2 Scheduled Operations

Cron runs php artisan schedule:run each minute. Scheduler in routes/console.php executes backup:auto daily at configured time/timezone with overlap prevention.

7. Data Model

  • User belongsTo Role; Role hasMany User
  • Artist hasMany Artwork; Location hasMany Artwork
  • Artwork belongsTo Artist and Location
  • Artwork hasMany ArtworkImage and Movement
  • Setting stores key-value configuration

8. Routing and Access Control

  • Routes in routes/web.php and routes/console.php
  • Middleware boundaries: guest, auth, admin
  • admin alias configured in bootstrap/app.php
  • PWA manifest route: GET /manifest.json

9. File and Image Handling

Service: app/Services/ImageOptimizer.php

  • Stores uploaded or URL-based images
  • Resizes/compresses via GD
  • Writes WebP/JPEG optimized images to public disk
  • Fallback stores original binary if transform unsupported

10. Backup and Recovery

  • Manual backup via POST /settings/backup/generate
  • Automatic backup via php artisan backup:auto
  • Backup files saved to storage/app/private/backups
  • Payload includes generated_at, timezone, connection, and tables
  • Automated restore flow is not exposed in production UI

11. PWA and Mobile Installability

  • public/manifest.json, public/sw.js, and icons in public/icons/
  • Manifest uses standalone display mode and maskable icons
  • Service worker provides cache-first fetch strategy for core assets

12. Environment Configuration

Template file: .env.example

  • Core app: APP_*
  • Database: DB_*
  • Session/cache/queue: SESSION_*, CACHE_*, QUEUE_*
  • Mail: MAIL_*
  • Filesystem/cloud: FILESYSTEM_DISK, AWS_*
  • Optional AI engine: BUPPLE_*

15. Deployment Guide

  • Recommended runtime: Ubuntu LTS, Nginx, PHP-FPM, MySQL, TLS
  • Deployment flow: pull, install, build assets, migrate, cache, restart services
  • Required cron shown below
* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1

16. Security Notes

  • Enforce HTTPS in production
  • Use strong APP_KEY and credentials
  • Restrict administrative accounts
  • Validate upload inputs and URL sources
  • Harden file permissions and backup access

17. Performance Notes

  • Use Laravel production caches
  • Monitor DB query performance as data grows
  • Move heavy operations to queues when needed
  • Offload large media/backup retention to object storage if required

18. Operations and Monitoring

Monitor uptime, latency, system resources, DB health, queue status, backup freshness, and storage/logs.

19. Troubleshooting Guide

19.1 Common Issues

  • Missing APP_KEY: run php artisan key:generate
  • Images missing: run php artisan storage:link
  • Assets missing: run npm run build
  • Schedule not running: verify cron + php artisan schedule:list

19.2 Useful Commands

php artisan route:list
php artisan migrate:status
php artisan optimize:clear
php artisan schedule:list
php artisan backup:auto

20. Command Reference

  • museum:import-xlsx {path} {--download-images}: imports spreadsheet data to artist/artwork/location entities
