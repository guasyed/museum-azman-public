1. Document Purpose

This document provides technical guidance for developing, deploying, operating, and maintaining Museum Azman. Target audiences include developers, DevOps/infrastructure engineers, technical support teams, and system administrators.

2. System Overview

Museum Azman is a web-based collection management platform supporting:

  • Artwork inventory lifecycle
  • Artist and location management
  • Artwork movement tracking
  • Reporting and export (CSV/PDF)
  • CSV/XLSX import workflows with optional image download
  • User approval, role administration, notification preferences, and activity logs
  • Configurable statuses, regional settings, timezone, and backup operations
  • Installable PWA behavior

3. Technology Stack

3.1 Backend

  • php >=8.2 <8.6
  • laravel/framework ^12.0
  • laravel/tinker
  • barryvdh/laravel-dompdf / dompdf/dompdf runtime PDF fallback currently present in vendor/
  • bupple/laravel-ai-engine (optional)

3.2 Frontend

  • Blade templates in resources/views
  • Vite build pipeline
  • Tailwind CSS 4
  • Vanilla JavaScript for suggestions, modal interactions, AJAX flows, notifications, install prompts, and PWA

3.3 Data and Storage

  • Database configurable via Laravel (sqlite default in .env.example)
  • Backup table-snapshot support for mysql, pgsql, and sqlite
  • Public disk for media and local private disk for backup JSON files
  • Application responses receive CSP headers through SetContentSecurityPolicy

5. Architecture

5.1 Runtime Request Flow

  1. Client request
  2. Route resolution in routes/web.php
  3. Middleware checks (guest, auth, admin)
  4. Controller orchestration
  5. Eloquent model operations
  6. Optional service layer processing through ImageOptimizer and ActivityLogger
  7. Blade, JSON, streamed CSV, PDF, file download, or redirect response

5.2 Scheduled Operations

Cron runs php artisan schedule:run each minute. Scheduler in routes/console.php executes backup:auto daily at configured time/timezone with overlap prevention.

6. Core Modules

6.1 Authentication Module

Controller: app/Http/Controllers/AuthController.php

  • Guest routes include login, registration, forgot password, and reset password.
  • Registration excludes owner and admin role requests, creates users as unapproved, and notifies approved admins.
  • Login blocks users whose is_approved flag is false.
  • Login, logout, and registration actions are recorded in activity_logs.
// routes/web.php
Route::middleware('guest')->group(function () {
  Route::get('login', [AuthController::class, 'showLogin'])->name('login');
  Route::post('login', [AuthController::class, 'login'])->name('login.perform');
  Route::get('register', [AuthController::class, 'showRegister'])->name('register');
  Route::post('register', [AuthController::class, 'register'])->name('register.perform');
});

Route::middleware('auth')->group(function () {
  Route::post('logout', [AuthController::class, 'logout'])->name('logout');
});

6.6 Movement Module

Controller: app/Http/Controllers/MovementController.php

  • Routes cover movement list, create, edit, update, and delete.
  • Movements sync the linked artwork status and destination location from the latest movement.
  • Logistics-handler users see only movements assigned to their exact responsible_handler name.
  • Admins can create/edit/delete any movement; assigned logistics handlers can edit/delete their own assigned movements but cannot create new movements.
  • Assignment changes notify responsible handlers when their notification preferences allow it; handler-originated updates notify approved admins.
$movement = Movement::create($request->validated());
$this->notifyResponsibleHandlerAssignment($movement);
$this->syncArtworkStatus((int) $movement->artwork_id);

6.8 Settings and Backup Module

Controller: app/Http/Controllers/SettingController.php

  • General organization profile, regional settings, notification preferences, and appearance settings
  • Configurable active/default artwork and movement statuses
  • Manual backup generation, backup download, backup deletion, and backup listing
  • Settings persistence through the key-value settings table
  • Admin-only sections: general, regional, backup, statuses, users/roles
  • User-accessible sections: notifications and appearance
  • Notification preferences are stored on the current user; admins also persist defaults in settings
  • Appearance supports light/dark theme, density, accent color, heading font, and body font
  • Saving settings clears cached currency/date-format helpers
$timezone = $this->getConfiguredTimezone();
$relativePath = $this->createBackupFile($timezone);

$this->saveSettings([
  'backup_last_file' => $relativePath,
  'backup_last_generated_at' => now($timezone)->toIso8601String(),
]);

6.10 Sorting and Table UX

Listing modules support query-based sorting with controller allowlists and clickable table headers.

  • /admin/users: name, email, role, status
  • /settings?tab=users-roles: name, email, role, status
  • /artworks?view=table: title, current_valuation, created_at (default)
  • /locations?view=list: name, type
  • /movements: artwork_title, from_location, to_location, date_out, expected_return_date, responsible_handler, reason, status
  • Query params: sort and direction (asc/desc)
  • Settings users table uses user_sort and user_direction
  • Active sort indicator in headers: ▲ / ▼
  • Filter state and view mode are preserved while switching sort
  • Related-field sorting uses controlled joins with base-table selection

6.11 Import and Activity Modules

  • CSV import UI: GET/POST /admin/imports/csv
  • CSV command: museum:import-csv {path} {--connection=} {--download-images} {--skip-images} {--fresh}
  • XLSX command: museum:import-xlsx {path} {--download-images}
  • Activity logs: GET /admin/activity-logs and app/Services/ActivityLogger.php
  • Activity logs capture action, description, authenticated user, IP address, user agent, optional subject type/id/label, and can be searched/filtered by admins.
  • Notifications cover new user registrations and movement assignment/update events when the notifications table is available.

6.12 Profile Module

  • Controller: app/Http/Controllers/ProfileController.php
  • Routes: GET /profile, PUT /profile, PUT /profile/password
  • Users can update profile name/avatar; only admins can update their own email address from the profile form.
  • Password updates require the current password and reject reusing the current password.
  • Profile and password changes are logged through ActivityLogger.

7. Data Model

  • User belongsTo Role; Role hasMany User
  • Artist hasMany Artwork; Location hasMany Artwork
  • Artwork belongsTo Artist and Location
  • Artwork hasMany ArtworkImage and Movement
  • Country normalizes artist country references
  • Status stores active/default status options
  • ActivityLog stores auditable user/admin events
  • Setting stores key-value configuration
  • User::isLogisticsHandler() recognizes the logistics-handler role slug and legacy handler role labels
  • User::isApproved() defaults legacy/null approval state to approved

8. Routing and Access Control

  • Routes in routes/web.php and routes/console.php
  • Middleware boundaries: guest, auth, admin
  • admin alias configured in bootstrap/app.php
  • Guest boundaries cover login, registration, forgot password, and reset password routes
  • Logistics-handler movement restrictions are enforced inside MovementController
  • PWA manifest route: GET /manifest.json
  • Maintenance route: GET /optimize-clear is protected by auth and admin middleware
  • Admin documentation route: GET /admin/technical-documentation serves this HTML file with X-Robots-Tag: noindex, nofollow

9. File and Image Handling

Service: app/Services/ImageOptimizer.php

  • Stores uploaded or URL-based images
  • Resizes/compresses via GD
  • Writes WebP/JPEG optimized images to public disk
  • Fallback stores original binary if transform unsupported
  • Stores gallery images in artwork_images; the first valid imported image can become primary_image_path

10. Backup and Recovery

  • Manual backup via POST /settings/backup/generate
  • Automatic backup via php artisan backup:auto
  • Backup files saved to storage/app/private/backups
  • Payload includes generated_at, timezone, connection, and tables
  • Automated restore flow is not exposed in production UI

11. PWA and Mobile Installability

  • Manifest uses standalone display mode and maskable icons

16. Security Notes

  • Enforce HTTPS in production
  • Use strong APP_KEY and credentials
  • Restrict administrative accounts
  • Keep registration approval enabled for non-admin/owner role requests
  • Validate upload inputs and URL sources
  • Harden file permissions and backup access
  • Keep maintenance and documentation routes behind admin/auth boundaries
  • Verify composer.json and composer.lock are aligned before deployment

17. Performance Notes

  • Use Laravel production caches
  • Monitor DB query performance as data grows
  • Move heavy operations to queues when needed
  • Offload large media/backup retention to object storage if required

18. Operations and Monitoring

Monitor uptime, latency, system resources, DB health, queue status, backup freshness, failed notification/email delivery, pending registrations, handler assignment name mismatches, and storage/logs.

19. Troubleshooting Guide

19.1 Common Issues

  • Missing APP_KEY: run php artisan key:generate
  • Images missing: run php artisan storage:link
  • Assets missing: run npm run build
  • Schedule not running: verify cron + php artisan schedule:list
  • PDF fallback fails: verify DomPDF dependencies are committed in Composer metadata

19.2 Useful Commands

php artisan route:list
php artisan migrate:status
php artisan optimize:clear

20. Command Reference

  • backup:auto: generates automatic DB snapshot backup

  • museum:import-csv {path} {--connection=} {--download-images} {--skip-images} {--fresh}: imports CSV artwork data with optional image and fresh-import modes
